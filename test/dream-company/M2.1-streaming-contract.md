# M2.1 — Dream Company streaming (SSE) contract

Backend + proxy for streaming are **done and verified**. This documents the SSE contract so the
frontend (Minh) can build the incremental UI. The existing JSON endpoints are **unchanged** — the
streaming endpoints are additive (`/stream` suffix), so nothing breaks if the FE isn't wired yet.

## Endpoints (call the Next.js proxy, same as the JSON ones)

| Streaming endpoint | Body (identical to the JSON route) | `done` payload |
|---|---|---|
| `POST /api/dream-company/analyze/stream` | `{ profile }` | `ProfileAnalysis` |
| `POST /api/dream-company/roles/stream` | `{ profile, analysis }` | `TargetRole[]` |
| `POST /api/dream-company/roadmap/stream` | `{ profile, analysis, selectedRoles }` | `RoadmapResponse` (`{ jobs, roadmap, jobsError }`) |

Auth: send the Supabase access token as `Authorization: Bearer <token>` (same as JSON calls —
`getAuthHeaders()`). The proxy forwards it.

## Event stream (`text/event-stream`)

```
event: open
data: {"ok":true}

event: delta
data: {"text":"{\n  \"marketLevel\": \"mid\", ..."}      // raw model text chunks, in order

event: done
data: { ...the fully parsed result object... }            // same shape as the JSON endpoint

event: error
data: {"status":504,"code":"TIMEOUT","message":"The AI service took too long..."}
```

- `open` — stream started (use to switch UI into "generating" state).
- `delta` — a chunk of the model's raw output text. Concatenating all `delta.text` reconstructs the
  raw JSON. **You do NOT need to parse partial JSON** — use deltas only to show motion/progress
  (e.g. a live token counter, a "writing…" shimmer, or a progress bar driven by delta count).
- `done` — the final, server-parsed, validated object. **Render from this**, not from the deltas.
- `error` — terminal failure. `code` ∈ `TIMEOUT` (504), `LLM_TRUNCATED` (502), `LLM_NOT_CONFIGURED`
  (503), `LLM_PARSE_FAILED` (500), `INTERNAL` (500), `BACKEND_UNAVAILABLE` (502, proxy-level).
  Show `message` and stop the spinner.
- Bad input (missing profile/analysis/roles) returns a normal **JSON 400** (not an SSE) — the proxy
  passes it through with the original status, so handle a non-`text/event-stream` response too.

## Suggested FE consumption (fetch + ReadableStream, since we send a bearer header)

`EventSource` can't set an `Authorization` header, so use `fetch` + a reader:

```ts
const res = await fetch('/api/dream-company/analyze/stream', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', ...(await getAuthHeaders()) },
  body: JSON.stringify({ profile }),
})
if (!res.headers.get('content-type')?.includes('text/event-stream')) {
  throw new Error((await res.json()).message)      // JSON 400/401 error
}
const reader = res.body!.getReader()
const decoder = new TextDecoder()
let buf = ''
for (;;) {
  const { value, done } = await reader.read()
  if (done) break
  buf += decoder.decode(value, { stream: true })
  const frames = buf.split('\n\n'); buf = frames.pop() ?? ''
  for (const frame of frames) {
    const ev = frame.match(/^event: (.*)$/m)?.[1]
    const data = frame.match(/^data: (.*)$/m)?.[1]
    if (!ev || !data) continue                      // skip ": keepalive" comments
    if (ev === 'delta') bumpProgress(JSON.parse(data).text)
    else if (ev === 'done') setResult(JSON.parse(data))
    else if (ev === 'error') showError(JSON.parse(data).message)
  }
}
```

Notes for robustness (AC: "xử lý mất kết nối/timeout gọn gàng"):
- The backend sends `: keepalive` comment lines every 15s — ignore them (they keep proxies from
  closing an idle connection during the model's think time).
- On network drop, `reader.read()` rejects — catch it, stop the spinner, offer retry.
- `roadmap/stream` runs the Exa job search first (a few seconds) before any `delta` — keep the
  "generating" state from the `open` event, don't wait for the first delta.
